\section{CANVAS: Modelo de Negócio e Estratégia}

O Business Model Canvas \cite{santos2024} ajuda a condensar, em uma única visão, os elementos essenciais da solução proposta. Para este projeto, o artefato serve para alinhar problema, público-alvo, parceiros e a operação necessária para sustentar uma plataforma de monitoramento aplicada à meliponicultura.

\subsection{Canvas proposto para a plataforma}

O Canvas elaborado para o SmartHive consolida os nove blocos do modelo de negócio com foco no contexto da meliponicultura. Em síntese, os principais elementos são:

\begin{itemize}
    \item \textbf{Proposta de Valor:} monitoramento contínuo e em tempo real da saúde das colmeias, relatórios com insights para melhorar a gestão e prevenção de doenças voltada ao aumento da produtividade melípona
    \item \textbf{Segmentos de Mercado:} meliponicultores e instituições de pesquisa ambiental e agrícola
    \item \textbf{Parceiros e Recursos:} cooperativas, associações de meliponicultores e instituições de pesquisa, apoiados por hardware IoT, sensores, plataforma de prototipagem (Arduino) e equipe técnica multidisciplinar
    \item \textbf{Fontes de Renda:} venda do dispositivo IoT, assinatura de serviços de monitoramento e relatórios, além de manutenção e atualização da plataforma
\end{itemize}

% ===== SWOT =====
\section{SWOT: Análise Estratégica}

A análise SWOT \cite{oliveira2023} permite organizar fatores internos e externos que influenciam a viabilidade da solução. No contexto da plataforma de meliponicultura, ela ajuda a transformar uma ideia técnica em um plano mais realista de implementação e evolução.

\subsection{Matriz SWOT do projeto}

A matriz SWOT elaborada para o SmartHive identifica os principais fatores que sustentam e que desafiam o projeto. Em síntese, destacam-se:

\begin{itemize}
    \item \textbf{Forças:} combinação inovadora de IoT, visão computacional e modelos de IA (como YOLO) em um nicho ainda pouco explorado, com detecção em tempo real, ação preventiva contra forídeos e confiabilidade técnica comprovada em provas de conceito
    \item \textbf{Fraquezas:} dependência de condições ambientais (iluminação, clima, sujeira na lente), diversidade de espécies que aumenta a complexidade do modelo, custo inicial de hardware e necessidade de infraestrutura de energia e internet no local
    \item \textbf{Oportunidades:} crescimento do mercado de meliponicultura, captação de editais (CNPq, CAPES, FAPs, EMBRAPA, SENAR), expansão da plataforma para outras ameaças e atividades, e parcerias estratégicas com associações e cooperativas
    \item \textbf{Ameaças:} concorrência futura de empresas com mais recursos, resistência cultural à adoção tecnológica, evolução de pragas que exige retreinamento contínuo e robustez do hardware frente a intempéries
\end{itemize}

A figura a seguir apresenta a matriz SWOT completa do projeto:

\begin{figure}[H]

\caption{Matriz SWOT da aplicação SmartHive}

\subsection{Recomendações Estratégicas}

Com base na análise SWOT, as principais estratégias devem focar em:
\begin{itemize}
    \item \textbf{Forças + Oportunidades:} aproveitar o diferencial tecnológico (IoT + IA) para captar editais de fomento e firmar parcerias com cooperativas e instituições de pesquisa
    \item \textbf{Forças + Ameaças:} reforçar a robustez do hardware e a precisão dos modelos de IA para se diferenciar de concorrentes e reduzir a resistência cultural à adoção
    \item \textbf{Fraquezas + Oportunidades:} usar projetos institucionais para ampliar a base de dados de espécies, validar em campo e financiar a infraestrutura inicial
    \item \textbf{Fraquezas + Ameaças:} prever operação offline, manutenção preventiva dos equipamentos e ciclos regulares de retreinamento do modelo para acompanhar a evolução das pragas
\end{itemize}

\section{UX/UI: Design de Interface e Experiência do Usuário}

UX (User Experience) e UI (User Interface) \cite{silva2025} são fundamentais para garantir que a plataforma seja útil em contexto real de uso. Como parte dos acessos tende a ocorrer em campo, a solução deve privilegiar leitura rápida, ações objetivas e indicadores visuais que permitam interpretar o estado das colmeias sem esforço excessivo.

No SmartHive, a interface foi pensada para apoiar o meliponicultor em tarefas essenciais, como consultar o estado geral dos apiários, acompanhar colmeias monitoradas, visualizar alertas e acessar informações de apoio. A organização das telas busca reduzir a complexidade da operação e transformar os dados coletados em informações claras para tomada de decisão.

\subsection{Diretrizes de interface}

\begin{itemize}
    \item Priorizar contraste alto para leitura rápida em ambientes externos
    \item Exibir status com semântica visual simples: normal, atenção e crítico
    \item Reduzir o número de passos nas rotinas de cadastro e edição
    \item Destacar eventos recentes e pendências logo na primeira tela
    \item Garantir linguagem objetiva para perfis técnicos e não técnicos
    \item Organizar os dados de sensores em componentes visuais de fácil interpretação
\end{itemize}

\subsection{Exemplo de Configuração CI/CD}

Exemplo de workflow mínimo em GitHub Actions para validar a aplicação conteinerizada:

\begin{verbatim}
name: ci

on:
  push:
    branches: [ main ]
  pull_request:

jobs:
  validate:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: web-smarthive
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: npm ci
        working-directory: web-smarthive/frontend
      - run: npm run build
        working-directory: web-smarthive/frontend
      - run: pip install -r requirements.txt
        working-directory: web-smarthive/backend
      - run: docker compose build
      - run: docker compose config
\end{verbatim}

\subsection{Métricas e SLA}

Para acompanhamento operacional, algumas métricas relevantes são:

\begin{itemize}
    \item \textbf{Disponibilidade do painel:} 99.5\% de uptime mensal
    \item \textbf{Latência média da API:} abaixo de 500ms para consultas principais
    \item \textbf{Tempo de subida local:} containers saudáveis após \texttt{docker compose up --build}

    \item \textbf{Integridade dos dados:} persistência centralizada no Supabase e volumes para arquivos locais
    \item \textbf{Lead time de mudança:} até 1 dia para ajustes de baixa complexidade
    \item \textbf{MTTR:} até 2 horas para restauração de falhas operacionais
\end{itemize}
